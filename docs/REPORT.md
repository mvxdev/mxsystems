## 2. ЭТАП 2 — Astro и редизайн

### Что сохранено 1-в-1
Все блоки и их порядок, раскладка колонок (что слева/справа, сколько колонок, как складывается на
телефоне), все тексты, цифры, цены, ссылки, якоря, адреса страниц (`/`, `/ro/`, `/en/`, `/privacy/`,
`/ro/privacy/`, `/en/privacy/`, `/ru/`, 404). EN — по-прежнему FastLoad первым. Автоопределение
языка (early.js), cookie-согласие, GA4/Pixel только после согласия, строгая CSP. Всё SEO этапа 1.

### Что изменилось визуально — по блокам
- **Основа**: дизайн-система `src/styles/tokens.css` — 12-колоночная сетка (контейнер 1320, поля 20→64,
  промежуток 16/24), шкала отступов от 8px, типографика на clamp(), 3 уровня фона и текста (WCAG AA),
  одна кривая движения, одно скругление 3px, зерно на фоне. Свои шрифты вместо Google Fonts.
  Типограф: неразрывные пробелы, цены, тире, переносы по дефису; ровные цифры у засечек.
- **Шапка**: прозрачная → после прокрутки фон с размытием и линия; активный пункт подчёркивается по
  секции на экране; язык — текущий в рамке; кнопка контурная на первом экране и оранжевая после
  прокрутки; на телефоне — полноэкранное меню с крупными пунктами и кнопкой внизу.
- **Hero**: заголовок крупнее (до 92px), живая схема: данные бегут сверху в центр и из центра вниз,
  узлы вспыхивают при приходе точки, рамка ядра светится в такт, наведение подсвечивает линию блока;
  анимация идёт только на экране. Три сноски с цифрами кейсов (4Power, FastLoad, CarBids). Первый экран 1440×900 помещается целиком;
  на 390×844 видны заголовок, текст и обе кнопки (над cookie-баннером).
- **Кейсы**: «Кейс 01» + линия + статус; заголовок и таблица «Клиент/Отрасль/Команда» на сетке 7/5;
  «Что сделали» — ритм линеек и оранжевые маркеры, жирное начало светлее; макеты как настоящий продукт
  (цветные полосы статусов, счётчики, тени), машина переезжает в «Готова», новый груз «4 сек назад»
  сверху, список растворяется внизу; KPI — крупные моно-цифры со счётчиком; «Стек» — метки.
- **Платформы**: три карточки одной высоты, строки выровнены через subgrid (цифры внизу на одной линии),
  «рамка браузера» с адресом над скриншотом, увеличение и сдвиг при наведении; AVIF/WebP.
- **Кто делает**: фото крупно (5 колонок), обработка под стиль (контраст, тёплый тон, затемнение к низу),
  цитата крупным курсивом с буквицей и оранжевой линией, подпись под фото.
- **Услуги**: таблица на той же 12-колоночной сетке (№ · услуга · что входит · срок · цена), подсветка
  строки при наведении, стрелка сдвигается; на телефоне — карточки, срок и цена с подписями.
- **Калькулятор**: свои поля и ползунок с оранжевой заливкой до ручки, сумма крупно моно и плавно
  пересчитывается (300 мс), «в месяц» рядом с суммой.
- **Как работаем**: путь из 4 шагов, линия прорисовывается при появлении; «Всё остаётся у вас» —
  три тонкие линейные иконки (ключ, документ, открытый замок).
- **FAQ**: плавное раскрытие по высоте, плюс → минус, открыт только один (name="faq").
- **Контакты**: строки во всю ширину, подсветка и уход стрелки вправо; Telegram оранжевый.
- **Футер**: крупный знак «MX.», три колонки, нижняя строка с городом и годами.
- **Cookie**: не выводится, пока не вписаны ID GA4/Pixel (`src/lib/tracking.ts`); с ID — компактный,
  на главной появляется, когда вводный текст ушёл с экрана; на телефоне — узкая полоса.

## 4. Выбор версии (обе с SEO)

### Вариант А — оставить старую
`main` уже содержит SEO-правки (= тег `v1-seo`). Выложить — обычный push:
```bash
git checkout main
```
```bash
git push origin main --tags
```
GitHub Actions опубликует статический сайт, как раньше.

### Вариант Б — принять новую
```bash
git checkout main
```
```bash
git merge astro-redesign
```
```bash
git push origin main --tags
```
Что произойдёт: в main придёт новый `.github/workflows/pages.yml` — GitHub Actions поставит
зависимости, соберёт Astro (withastro/action), прогонит `seo_check.py` по dist/ и, если ошибок нет,
опубликует. Если SEO-проверка упадёт — сайт останется прежним. Настройки Pages менять не нужно
(источник уже «GitHub Actions»), домен — из `public/CNAME`.

### Откат с новой на старую после выкладки (только на v1-seo)
Откат делается новым коммитом: история не переписывается, force push не нужен.
1. Перейти в main:
```bash
git checkout main
```
2. Убрать из рабочей папки все файлы новой версии (только из git, история остаётся):
```bash
git rm -r -q .
```
3. Вернуть ровно те файлы, что были в v1-seo (включая старый workflow публикации):
```bash
git checkout v1-seo -- .
```
4. Проверить, что это старая версия и SEO в порядке (должно быть «ошибок нет»):
```bash
python tools/seo_check.py .
```
5. Зафиксировать и опубликовать:
```bash
git commit -m "Откат на v1-seo"
```
```bash
git push origin main
```
GitHub Actions выложит статический сайт v1-seo. Папки node_modules/ и dist/, если остались на диске,
в git не попадают (.gitignore) — их можно удалить вручную.

## 5. Что сделать руками

**Google Search Console** (search.google.com/search-console, ресурс mxsystems.md уже подтверждён):
1. Слева «Файлы Sitemap» → в поле ввести `sitemap.xml` → «Отправить».
2. Сверху «Проверка URL» → вставить `https://mxsystems.md/` → «Запросить индексирование».
   Повторить для `https://mxsystems.md/ro/` и `https://mxsystems.md/en/`.
3. Через 3–7 дней: «Страницы» (индексирование) и «Улучшения» → проверить, что ошибок нет.

**Bing Webmaster Tools** (bing.com/webmasters): войти Google-аккаунтом → «Импорт из Google Search
Console» → выбрать mxsystems.md → «Импорт». Sitemap подтянется сам (Bing также питает DuckDuckGo и ChatGPT-поиск).

**Яндекс Вебмастер** — для Молдовы оцениваю как необязательный: русскоязычная аудитория в Кишинёве
ищет в основном в Google. Если хочется охвата — webmaster.yandex.com → «Добавить сайт» → подтверждение
мета-тегом (нужно будет вставить тег в Layout) → «Индексирование → Файлы Sitemap». 10 минут, вреда нет.

**Google Business Profile** (business.google.com) — «Добавить компанию» → «MX Systems», категория
«Разработчик ПО» / «Веб-дизайнер» → если клиентов не принимаете в офисе, выбрать «Обслуживаю клиентов
на их территории» и указать зону: Кишинёв, Молдова → телефон, сайт → подтверждение (код по почте/видео).
Без реального адреса на сайте разметку адреса я не добавлял.

**Cloudflare** (dash.cloudflare.com → домен mxsystems.md):
1. SSL/TLS → Overview → режим **Full** (или Full (strict)).
2. SSL/TLS → Edge Certificates → **Always Use HTTPS: On** (сейчас http отдаёт 200 без перехода).
3. Редирект www → без www: Rules → Redirect Rules → Create rule → «Custom filter»: Hostname equals
   `www.mxsystems.md` → Then: Dynamic, выражение `concat("https://mxsystems.md", http.request.uri.path)`,
   код **301**, «Preserve query string» — вкл. (В DNS должна быть запись `www` с оранжевым облаком.)
4. mxsystems.ro → mxsystems.md/ro/: добавить домен mxsystems.ro в Cloudflare (если ещё не), DNS-запись
   `@` (A 192.0.2.1, прокси вкл.) и `www`; Rules → Redirect Rules → правило: Hostname is in
   `mxsystems.ro www.mxsystems.ro` → Dynamic, `concat("https://mxsystems.md/ro", http.request.uri.path)`,
   **301**, сохранять строку запроса.
Плюс отложенный пункт «безопасность»: HSTS, заголовки, SPF/DMARC, 2FA — по вашему сигналу.
